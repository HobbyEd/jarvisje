Overzicht van de end-to-end flow van de Sogyo Kennis Chatbot, van browser tot LLM en het indexeringsproces.

Hoe de flow werkt (stap voor stap):

  1. Browser: Gebruiker opent jarvisje.com. Cloudflare Tunnel stuurt veilig door naar de host (poort 8080).
  2. Host & Container: Docker container sogyo-chatbot-app (8001). FastAPI serveert UI en API.
  3. Chat / Retrieval: Query wordt ge-embedded met BGE-M3 (CPU) en gezocht in Chroma.
  4. Lokaal LLM: Context + vraag naar Ollama gemma3:4b op de GPU van dezelfde server.
  5. Antwoord: Streaming tokens + bronnen terug naar de browser.

Alles draait op één host (.15): app, embeddings, vector store en LLM. Geen DGX nodig voor de productiechabot.

Elke stap is traceerbaar: van vraag tot antwoord, volledig op de lokale server.

1. Chat Flow (Vraag → Antwoord)

  1. Gebruiker stelt vraag in de browser
  2. Request via Cloudflare Tunnel naar host:8080 → container:8001
  3. FastAPI ontvangt POST /chat
  4. Retrieval: Vraag → BGE-M3 embedding → Chroma similarity search
  5. Context + vraag → Ollama gemma3:4b (OpenAI-compatible, lokaal op GPU)
  6. LLM streamt tokens terug via SSE
  7. Browser toont antwoord met bronnen

Retrieval en LLM draaien lokaal op de productieserver.

2. Indexeringsproces (Kennisbank opbouwen)

  • Start via UI → POST /ingest/start spawnt een apart worker-proces (ADR-010)
  • Worker: scrape → chunk → embed → upsert; chat-API blijft beschikbaar
  • Status via gedeeld bestand op data-volume; UI pollt GET /ingest/status
  • Zelfde entrypoint voor CLI/cron: python -m sogyo_chatbot.ingestion.worker
  • Data blijft in persistente volume /home/evdillen/sogyo-chatbot-data
Belangrijke componenten: FastAPI (backend), BGE-M3 (embeddings), Chroma (vector store), Ollama gemma3:4b (LLM op GPU), Cloudflare Tunnel (publieke exposure).
